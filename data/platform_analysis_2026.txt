 
 Developer Distribution Platforms 2026 
 Where to point a solo build pipeline in 2026 
 Thirty-nine developer distribution platforms, scored on organic traffic, willingness to pay, saturation, speed to publish and solo monetizability. Chrome Web Store is the incumbent baseline and it is measured with first-party data, not estimated. 
 Measured 2026-09-01, revised after a second measurement round · 39 platforms · 19 live APIs · ~90,000 listings with outcome data · 55 framework repos verified 
 Section 0 · Final decision · consolidated 2026-09-02 · confidence 91/100 
 Allocate 70% of build capacity to Telegram Mini Apps behind a 14-day gate, 20% to MCP servers, 10% to Atlassian Forge. Standardise on TypeScript. Ship nothing new to Chrome. 
 The decision, leg by leg, each carried by measurement: 
 70% — Telegram Mini Apps (framework: grammY , reliability 91/100). The only surface measured here that combines absorption of a 30–50bn-token pipeline (no listing review, no meaningful cap shape), a documented native billing rail (Stars/XTR, mandatory for digital goods), a billion-plus user pool (Durov’s channel, verbatim), a nearly empty shelf (ton.app catalog: ~259 apps total; GitHub: 490 Mini App repos vs 26,879 MCP), and a measured demand upper tail — indie badge-holders median 83,714 MAU, max 1.30M, via the t.me badge instrument found in the challenge round. Gated: capacity flows only after 2 unpromoted bots run 14 days; the t.me badge (~10k threshold) and bot logs score the result objectively. Fail → the 70% moves to MCP. 
 20% — MCP servers (framework: @modelcontextprotocol/sdk , 89/100, still 1.x). Fully measured: capture ratio 1.17 vs Chrome’s 0.033, zero publish friction, protocol verified end-to-end on this machine in under a minute — and zero billing, so it is an option on 2027, never the revenue. Start with the two measured empty slots: price tracker and time tracker (0 MCP servers vs 683 and 897 Chrome listings). 
 10% — Atlassian Forge (3–5 apps by hand; the toolchain blocks agents — scaffold produced zero files without credentials). The revenue anchor: $0.80/user/month median price measured across 1,277 live pricing pages, $960/yr per 100-seat customer, 19.3% median fair-share capture — both instruments point here independently, and the pessimistic conversion case still clears 508× a Chrome listing. 
 0% — Chrome Web Store, on every branch. All four accounts at the 20-listing cap, $8.42/listing/yr measured, new-entrant capture 0.033. The estate is a maintenance asset: the retrofit play on the 8 listings holding 96.72% of installs remains the only Chrome action with positive expected value.

 Why this decides the framework question. An agent pipeline breaks on two things: an API that changes underneath generated code, and a command that stops to ask a human something. grammY and the MCP TypeScript SDK have neither — zero major bumps in a year, and both went from empty directory to verified running product with no account, no key and no network login . The Forge and Shopify CLIs both stopped and asked for credentials before emitting a single file. That is the whole argument.

 1  How this was measured 
 Everything labelled measured was pulled live from a public API on 2026-09-01. Nothing in that class is recalled from training. 
 Chrome Web Store — the store's own ds:1 search payload and ds:0 detail payload. 53,555 unique listings with install counts (sweep of 224 query slots, 2026-08-18); 199 top-10 listings and a random 600-listing catalogue sample dated by first-published epoch ds0[0][17][0] , resolved today. 
 MCP — full crawl of registry.modelcontextprotocol.io/v0/servers?version=latest , 261 pages, 26,098 unique servers. Smithery registry.smithery.ai/servers for the top 500 by use, plus a 63-term query sweep yielding 4,811 unique servers with use counts. 
 Others — VS Code extensionquery API (138,357 listings, install statistics for 1,800 of them), Firefox AMO v5 search API, WordPress.org plugins API, Atlassian rest/2/addons , Raycast store_listings (33 pages), Open VSX search, Homebrew formula + 365-day analytics JSON, Obsidian community-plugin-stats.json , npm replicate doc_count , PyPI simple index, GitHub topic search. 
 First-party Chrome economics — your own Stripe live export and fleet install baseline, previously reconciled against checkout_sessions.ndjson . This is why Chrome is the only platform here with a verified revenue-per-install figure. 
 Second round — the four platforms whose scores decided the top of the ranking were promoted from inference to measurement: Atlassian (full 6,137-app crawl plus live pricing for 1,277), Shopify (25,778 sitemap URLs, 449 sampled for structured data and prices), JetBrains (full 10,000-plugin crawl) and WordPress (4,000 plugins across 40 random pages). Plus 55 framework repositories via the authenticated GitHub API and six npm download series. 
 What still could not be measured. Slack, Figma, Google Workspace, Edge Add-ons, Microsoft Store and the mobile stores render their counts client-side with no reachable JSON endpoint, and the browser bridge is not connected this session; top.gg and PulseMCP sit behind Cloudflare or a sunset API; Glama requires an API key. Those rows stay Low or Med confidence, are marked inferred in the ranked table, and every number in them is listed in section 10. 
 Read the ranked table with section 4 open. Every platform that moved from inferred to measured scored lower — four for four, mean −8 points. The inferred rows have not had that correction applied, so they sit higher than they probably deserve. 
 2  The finding that decides it 
 Saturation is usually reported as catalogue size. Catalogue size is the wrong measure — what matters is whether a new listing can reach the top. 
 Chrome's catalogue is young : 43.5% of a random sample of 593 live listings were first published in 2026, and the median swept listing is 0.8 years old. Chrome's top slots are old : across 20 common queries, the 199 listings holding a top-10 position have a median age of 6.6 years , and only 3 of them (1.5%) were published in 2026. New supply floods in at roughly 4.8% of the catalogue per month and captures almost nothing. 
 MCP inverts this. Across an independent 63-term sweep of 4,811 servers , the 2026 cohort is 70.5% of servers and holds 82.5% of all recorded use — new entrants are over -represented in outcomes, not under-represented. The same measurement on Chrome’s dated sample gives 43.5% of listings holding 1.43% of install mass. As a capture ratio (share of outcome ÷ share of catalogue): MCP 1.17, Chrome 0.033 — a 35.5× like-for-like difference. 
 How this finding was hardened. Its first version used Smithery’s default 500-result ranking, where 87% of entries are 2026 vintage. That listing turned out not to be strictly usage-ranked — the independent sweep found 241 servers with use counts above the listing’s floor that were absent from it — so the 500-list is reported here only as what a browsing user sees, never as “most used”. The capture ratios above are derived instead from the 4,811-server sweep and the 593-listing Chrome sample, both independent of any platform sort order. Chrome’s ratio also triangulates: from top-10 search rankings it is 0.0347 , from install mass 0.0329 . Two methods, same answer. 
 The cohort medians say it more bluntly. A Chrome listing first published in 2026 has a median of 7 installs ; one published earlier has 113 . Arriving late on Chrome costs you 16× before you write a line of code.

At your own measured Chrome rate of $0.07934 per install per year, matching that single customer requires 12,100 Chrome installs — roughly 114 years of output from one median Chrome listing, or a third of your entire 40,102-install estate. 
 The same logic, stated as the trap you are currently in: your fleet’s 8 best listings hold 96.72% of 40,102 installs and the whole estate produced $3,711.76 in 22 months.  Fair-share capture — the metric that reframes saturation

Compare that against what the median listing actually gets, and you have the share of its own fair share that a typical listing captures.  E8 Build-cost multipliers (Shopify ~5–10× a Chrome extension; MCP lower than Chrome). Engineering judgement, not measured. Build one of each through your pipeline and compare wall-clock to first submission. 
 E9 Review times and rejection rates across Apple, Google, Shopify, Atlassian, Salesforce, Workspace. Recalled from training, not verified today, and policy volatility is high. Any current developer-policy page. Treat all speed-to-publish scores except Chrome's as provisional. 
 E10 "MCP reaches Chrome's slot depth in 12–18 months." A linear-to-exponential extrapolation from 13 months of supply data. Re-run the registry crawl monthly. If monthly first-publishes fall below ~5,000, the window is wider than stated. 
 E11 JetBrains “downloads” approximate users. The API reports cumulative downloads across every version, so auto-updates inflate the figure by an unknown multiple. The median of 2,866 is therefore an upper bound on users, and is not comparable to a Chrome install count. Compare a plugin’s download count against a known user figure from its own telemetry or vendor. If the ratio exceeds ~5×, JetBrains’ organic score drops from 3 to 2 and it falls out of the measured top three. 
 E12 Shopify review counts proxy for customers. 94.4% zero-review does not strictly prove 94.4% have no users; review rates vary by category and prompt design. Any Shopify app with a public install or revenue figure, compared against its review count. If typical review-to-install ratios are under ~0.1%, zero reviews is compatible with hundreds of users and Shopify’s organic score should return to 3. 
 E13 Atlassian installs convert to paying customers at a meaningful rate. Cloud apps are free under 10 users, so an unknown share of the median app’s 11 installs pay nothing. The $960/customer figure is a measured price , not measured revenue. Atlassian does not publish conversion. A vendor disclosure or your own first listing would settle it. If under ~10% of installs sit above the free tier, the median app earns closer to $1,000/yr than $9,000/yr — still ~500× a Chrome listing, so the ranking holds even under the pessimistic case.
